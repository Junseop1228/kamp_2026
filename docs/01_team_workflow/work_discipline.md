## WD-01. 단일 권위 소스

모든 보고 수치는 `results/metrics.json` 한 곳에서만 나온다. 보고서·발표자료·README에 손으로 숫자를 입력하는 것을 금지한다.

- 파이프라인 실행 → metrics.json 갱신 → 문서는 여기서 인용
- 파이프라인 밖에서 노트북으로 따로 돌린 결과는 문서에 넣지 않는다. 넣어야 하면 먼저 파이프라인에 편입시킨다

KAMP 특수 조건 — 같은 수치가 보고서 PDF, 발표자료 PDF, 발표자료 PPT, 소스코드 출력 **네 곳**에 들어간다. 한 곳만 스테일이어도 제출 후에는 되돌릴 수 없다.

작성 경로를 고정한다.

metrics.json → 보고서 초안(.md) → 검사기 통과 → 주최 측 양식으로 이관

처음부터 주최 양식 파일에 직접 타이핑하기 시작하면 WD-01은 그 시점에 무력화된다. 양식 이관은 마지막 단계에서 한 번만 한다.

## WD-02. 자동 정합성 검사기

`src/check_report.py`를 만든다. 보고서 초안에서 숫자를 정규식으로 긁어 metrics.json과 대조하고, 불일치 시 exit 1로 죽는다. 제출 전 반드시 통과를 확인한다.

- **검사기 자체를 검증한다.** 일부러 틀린 샘플 문자열 5~6개를 넣어 전부 CATCH되는지 확인한 뒤에 신뢰한다
- **제작 시점은 준비기(~09-17)다.** 실행기 14일 안에 새로 만들면 순손실이다
- **범위는 .md 초안 + metrics.json 대조까지.** PDF/PPT 역추출은 주최 측 양식이 공개(09-21)된 뒤에 검토한다

## WD-03. AI 산출물 신뢰 등급

AI가 생성한 것은 검증 전까지 신뢰하지 않는다.

| 대상 | 검증 방법 |
|---|---|
| 코드 | 예상값을 아는 입력 최소 1개로 실행해 대조 |
| 수치 인용 | 원본 파일·로그에서 직접 확인. 확인 못 하면 "미확보" 표기 |
| 문헌 인용 | 실제 URL을 열어 확인. 제목·저자·연도 대조 |
| 도메인 주장 | 출처 명기. 출처 없으면 "가설" 표기 |

그럴듯한 숫자가 나오면 반드시 역추적한다. 출처가 붙지 않는 수치는 문서에 넣지 않는다.

## WD-04. 편집 후 재확인 (write ≠ correct)

파일 수정은 3단계다.

1. 앵커 문자열이 정확히 1회 매칭되는지 먼저 확인
2. write 실행
3. 다시 읽어서 새 내용이 들어갔는지(must_appear) + 옛 내용이 사라졌는지(must_vanish) 검증

기계적 치환 후에는 값의 자릿수를 눈으로 확인한다. 가수만 바뀌고 지수가 남는 유형의 오류는 검사기도 놓칠 수 있다.

## WD-05. 그림·표에 값 하드코딩 금지

matplotlib 라벨, 표 캡션, 주석에 숫자를 직접 쓰지 않는다. 전부 metrics.json을 참조한다.

발표자료가 최대 위험 지점이다. PPT 안에서 도형·텍스트로 그래프를 만들지 않는다.

- 모든 figure는 `src/viz/` 스크립트가 생성해 `results/figures/`에 저장한다 (`outputs/`는 gitignore 대상이라 팀 공유가 안 된다)
- PPT·보고서에는 생성된 이미지 파일만 넣는다
- 수치가 바뀌면 스크립트 재실행 한 번으로 전부 갱신되는 상태를 유지한다

## WD-06. 결과가 인공물인지 먼저 의심한다

수치를 보고하기 전에 아래를 확인한다. 이 항목은 배점과 직접 맞물린다 — 분석 과정 타당성(10) + 결과해석 우수성(10) + 발표 분석 과정 적절성(20).

- **시드** — 단일 시드 결과로 모델을 선택하지 않는다. 최소 3~5시드의 평균과 표준편차를 함께 본다. 소수 셋째자리 차이는 차이가 아니다
- **데이터 누수** — 비정상적으로 좋은 성능(AUC 0.99 등)이 나오면 성과가 아니라 누수를 먼저 의심한다. 시간 기반 분할 위반, 타깃에서 파생된 변수, 전처리 통계를 전체 데이터로 계산한 경우
- **정밀도** — 자릿수를 늘려 보고하려면 그 정밀도에 근거가 있어야 한다. 재현 실행에서 흔들리면 자릿수를 줄인다
- **통제변수(ablation)** — "A가 성능을 올렸다"는 주장은 A만 제거한 대조 실험이 있을 때만 한다

마지막 항목이 특히 중요하다. **물리 기반 파생변수의 가치는 ablation 없이는 증명되지 않는다.** 넣었더니 성능이 올랐다는 서술과, 그 변수만 뺀 대조군을 제시하는 것은 심사에서 다른 물건이다. 도메인 축의 기여를 배점으로 바꾸는 유일한 통로다.

## WD-07. 결정 로그와 실험 로그 분리

- `docs/03_decision_log.md` — 무엇을 왜 결정했는가. 틀린 초기 가설은 지우지 말고 정정 기록과 함께 남긴다
- `experiments/log.md` — 실행한 실험, 시드, 파라미터, 결과

"어떤 가설을 언제 어떻게 폐기했는가"는 발표평가에서 감점 소재가 아니라 가점 소재다. 기록이 없으면 주장할 수 없다.

## WD-08. 선행 확인 후 차별점 주장

"우리 접근의 새로운 점"을 쓰기 전에 반드시 선행 사례를 확인한다. 이미 선점된 항목은 즉시 차별점 목록에서 제거한다. 심사자가 먼저 발견하는 것보다 스스로 빼는 게 낫다.

검색 대상은 두 축이다.

1. 논문·공개 구현
2. **제2~5회 발표평가 진출작 34팀** (`docs/reference/past_rounds.md` 4절)

2번을 빠뜨리기 쉽다. 진출작 제목과 겹치는 구성을 차별점으로 내세우면 심사위원이 먼저 안다. 독창성 배점 서면 10 + 발표 20 = 30점이 걸려 있다.

## WD-09. 작업 순서와 결과 동결

- **계산이 서술을 결정한다.** 수치가 흔들릴 가능성이 있으면 계산을 먼저 끝내고 글을 쓴다
- **번호 재배치는 단독 작업, 단독 커밋.** 다른 편집과 섞으면 실패 지점이 늘어난다
- **각 단계 종료 조건은 동일하다** — 검사기 0건 + 커밋 완료

**결과 동결일 10-05 24시.** 이후 모델 실험·하이퍼파라미터 변경을 금지한다. metrics.json을 동결하고 문서·그림·검사기 작업만 한다. 예외는 명백한 버그 수정뿐이며, 수정 시 전체 문서를 재검사한다.

10-06 ~ 10-08은 문서 작업 전용 구간이다. 마감 시각이 미확보이므로 오후 마감을 가정한다.

## WD-10. 세션 경계 관리

세션 종료 시 채팅에만 남기지 않는다. `docs/05_session_handoff.md`에 현재 상태 · 다음 액션 · 미해결 항목을 파일로 기록한다.

AI 대화가 길어지면 먼저 세션 전환을 제안하도록 지시한다. 실행기 14일 동안 세션은 수십 개가 되고, 채팅에만 있는 결정은 존재하지 않는 결정이다.

## WD-11. 환경 함정 (Windows)

- PowerShell 에러가 안 보이면 `2>&1 | Out-String -Width 200`을 붙인다
- 파일 인코딩 UTF-8 고정. LF/CRLF 혼용 주의 (`.gitattributes`에 `eol=lf` 설정됨)
- 한글 커밋 메시지는 UTF-8 파일로 분리 후 `git commit -F`
- **matplotlib 한글 폰트** — 제출 노트북에서 글자가 깨지면 심사위원 화면에 그대로 노출된다. 폰트 설정을 `src/utils/`에 공통 함수로 두고 전 스크립트가 호출한다
- **개발환경 이원화** — 로컬 / KAMP-NOTE / AI-PaaS 중 어디서 돌려도 같은 결과가 나와야 한다. 절대경로 금지, 경로는 `config.py` 경유

## WD-12. 커밋 설명 책임 (3인 전원)

AI가 짠 코드를 그대로 커밋하지 않는다. **무엇을 하는 코드인지 한 문장으로 설명할 수 있어야 커밋한다.**

설명할 수 없는 코드는 발표평가 질의응답에서 방어할 수 없다. WD-03과 같은 이유다.

이 규칙은 코드에만 적용되지 않는다. 자기가 설계한 파생변수의 근거, 자기가 고른 지표의 이유도 동일하게 한 문장으로 설명할 수 있어야 한다.

## WD-13. 제출 노트북 재현성

`.ipynb`는 심사위원이 직접 열어보는 제출물이다. 공고에 부정제출 배제 조항이 있다.

제출 전 확인 항목이다.

- 커널 재시작 후 위에서 아래로 순차 실행 시 에러 없음
- 난수 시드 고정 (numpy / random / 프레임워크별)
- 절대경로 없음. 데이터 경로는 상대경로 또는 config 경유
- 실행 환경 명시 (`environment.yml` 또는 requirements)
- 셀 출력이 최종 metrics.json과 일치 (WD-01)
- 한글 폰트 깨짐 없음 (WD-11)
