# 의사결정 로그

이 문서는 **선택의 기록**이다. 오류의 기록은 `../known_issues/`에 남긴다.

틀린 것으로 판명된 결정을 지우지 않는다. 정정 기록을 아래에 덧붙인다. "어떤 가설을 언제 어떻게 폐기했는가"는 발표평가에서 방어 논리가 된다 (WD-07).

## 형식

각 항목은 `D-NNN`. 번호는 재사용하지 않는다. 아래 항목을 채운다.

> 일자 / 상태(확정·잠정·폐기·정정) / 결정 / 배경 / 대안과 기각 사유 / 감수한 리스크 / 재검토 시점

## D-001. GitHub 리포지토리를 Public으로 공개

- **일자** 2026-08-24
- **상태** 확정
- **결정** `github.com/Junseop1228/kamp_2026`을 Public으로 운영한다.
- **배경** 무료 계정에서는 Private 리포에 브랜치 룰셋(Rulesets)을 적용할 수 없다. `main` 직접 push 차단을 서버 측에서 강제하려면 공개 전환이 필요했다.
- **대안과 기각 사유**
  - Private 유지 + 유료 플랜 — 대회 단발 용도에 결제할 근거가 부족하다고 판단
  - Private 유지 + `.githooks/pre-push` 클라이언트 훅 — 우회 가능하고(`--no-verify`) 3인이 각자 설정해야 해서, 설정 누락 시 조용히 무력화된다는 점을 들어 기각
- **감수한 리스크** (아래는 실현 가능성을 인지하고 수용한 것이다)
  1. 전략 문서 노출 — `docs/reference/past_rounds.md`(과거 4회 배점 구조·진출작 34팀 경향 분석), `docs/01_team_workflow/work_discipline.md`(배점 대응 논리)가 모집 기간 중 검색 가능해진다
  2. 제출물 선점 시비 — 공고에 부정행위·부정제출 배제 조항이 있다. 유사 제출물이 나올 경우 원본 소명 부담이 생길 수 있다
  3. 비가역성 — 공개 이후 Private으로 되돌려도 그 사이 복제된 사본은 회수할 수 없다
- **완화** 커밋 이력 자체가 시점 증거가 된다. 제출 시점에 `submission-2026-10-08` 태그를 남겨 선후관계를 고정한다 (git_policy 8절).
- **재검토 시점** 없음. 비가역 결정이다. 다만 리스크 1이 실제 피해로 확인되면 `known_issues/`에 등록한다.

## D-002. 복수 데이터셋 결합을 전략 전제에서 제외

- **일자** 2026-08-28
- **상태** 확정 (D-002a 가설 폐기에 따름)
- **결정** 복수 제조AI데이터셋을 결합하는 접근을 전략 전제에서 뺀다. 분석·연습·제출은 단일 데이터셋 안에서 2단 이상을 엮는 형태로 설계한다.
- **배경** 카탈로그 수집(WO-001) 중 동일 설비 데이터가 분석목적별로 분리 등재된 쌍을 발견했다(no.47/48 열처리 — 주 데이터 row 2,939,722 일치, no.49/50 의류 — 레코드·용량 일치). 여기서 "결합하면 데이터 활용도 점수에 유리하다"는 가설을 세웠다(D-002a).
- **폐기 근거** 과거 4회 과제공개 원문을 대조한 결과 정반대였다.
  - 제2~4회 — 데이터셋을 단수로 지정 ("용해탱크 제조AI데이터셋" 등)
  - 제5회 — "팀별 **1종**의 제조AI데이터셋을 선택하여 제조AI 분석"으로 명시
  - 진출작 34팀 제목에 복수 데이터셋 사용 사례 없음. 전부 단일 데이터셋 내 다단 구조
  즉 결합은 유리한 전략이 아니라 규정 위반이었다.
- **혼동의 정체** "단일 모델 제출 금지" 원칙은 **모델 단계가 2개 이상**이라는 뜻인데, 이를 **데이터셋이 2개 이상**으로 바꿔 읽었다. "예측 + 원인분석"은 단일 데이터셋으로 성립한다.
- **제6회 문구 해석** 공고문 "50종 중 1종 또는 여러 종을 활용하여 문제 출제 예정"의 주어는 출제자다. 참가팀 재량이 아니다. 출제자가 실제로 여러 종을 묶어 낼 가능성은 남아 있으나, 그 경우 결합은 강제되는 것이지 우리가 선택하는 것이 아니다. 9/21 과제공개에서 확인한다.
- **감수한 리스크** 제6회가 실제로 복수 데이터셋 과제로 나올 경우 결합 경험이 없는 상태로 진입한다. 다만 데이터셋 **내부** 다중파일 처리(no.36의 정상/이상 분리 등)는 Sprint 1에서 그대로 겪으므로, 조인 자체가 미경험 영역이 되지는 않는다.
- **재검토 시점** 2026-09-21 과제공개 수령 직후

## D-003. Sprint 1 대상을 no.36 소성가공 품질보증으로 확정

- **일자** 2026-08-28
- **상태** 확정
- **결정** Sprint 1(9/1~9/7) 연습 대상을 `no.36 소성가공 품질보증 AI 데이터셋` 단독으로 한다.
- **배경** D-002로 결합 전제가 빠지면서 후보 재산정이 필요했다.
- **선정 기준** ①단일 데이터셋 안에서 2단 이상 설계 가능 ②7일 안에 문서까지 도달하는 회전속도 ③결과의 타당성을 대조할 기준선 존재 ④도메인 담당의 투입 여지
- **선정 이유**
  1. **제5회 선택지 ② 그 자체다.** 실제로 출제된 문제를 그대로 푸는 것이 리허설 정의에 가장 가깝다. 진출작이 기준선이 된다
  2. **1.61MB로 후보 중 가장 가볍다.** 리허설의 목적은 파이프라인 결함 노출인데, 대용량이면 파이프라인이 아니라 I/O를 디버깅하게 된다
  3. **압출성형기 변수(수지온도·압력·모터속도)가 화공 도메인에 직접 닿는다.** 물리 기반 파생변수 설계가 실제로 산출될 수 있는 축이며, 이는 정성 배점 30점(제조현장 문제 이해도 + 제조AI데이터셋 이해도 + 결과해석 우수성)에 대응한다
  4. 라벨(양/불량)이 명시돼 있어 지도학습 파이프라인 전 구간이 첫날부터 돌아간다
- **대안과 기각 사유**
  - `no.40 주조 공정최적화`(8.18MB) — 제4회 진출작 10팀으로 기준선이 가장 두껍다. 다만 2026.07.13 수정본이라 진출작과 데이터가 다를 수 있고, 다이캐스팅은 화공보다 재료·주조 도메인이라 도메인 투입 효율이 떨어져 기각
  - `no.48 열처리 공정최적화`(481MB) — 구조는 가장 실제적이나 7일 내 문서 도달 불가로 기각. 6절에 보류 항목으로 남겨 로딩 시간 실측만 시도
  - `no.35 소성가공 예지보전`과의 병행 — 설비가 다르므로(유압펌프 모터 대 압출성형기) 결합 대상이 아니다. 보조 트랙으로만 둔다
- **감수한 리스크**
  1. 소규모 데이터라 대용량 처리에서 드러나는 결함(메모리, 청크 로딩)을 Sprint 1에서 못 잡는다 → 보류 항목의 481MB 로딩 실측으로 부분 보완
  2. 제5회 대상이라 제6회 재출제 가능성이 낮다. 연습 내용이 그대로 재사용되지는 않는다 → 애초에 이전되는 것은 코드 모듈과 프로토콜이지 특정 데이터 분석 결과가 아니다
- **재검토 시점** Sprint 1 종료 시(9/7) 회고에서 판정
